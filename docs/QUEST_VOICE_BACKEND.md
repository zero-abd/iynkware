# Quest voice backend

This optional service gives a native Meta Quest Unity build a bounded push-to-talk voice loop:

`Quest microphone → HTTPS upload → Gemini Live WebSocket → native audio reply → WAV playback`

The Gemini key stays on the companion service. The APK contains only a replaceable demo client token. For the hackathon this is intentionally a turn-based Quest-to-backend flow; the backend uses Gemini Live's stateful WebSocket and native audio response.

This is an isolated hackathon companion, not the canonical collaboration server in `server/` and not the repository's future WebXR foundation. It does not change shared contracts or invent WebXR folders. The Unity files under `integrations/` are an external adapter for the separate Meta Horizon project.

## Run locally

```bash
cd quest-voice-backend
cp .env.example .env
npm test
npm run dev
```

`GET /healthz` and `GET /readyz` are public (`GET /health` is a host-compatible alias). `POST /v1/voice/turn` requires `Authorization: Bearer <IYNK_VOICE_CLIENT_TOKEN>` and multipart fields `audio`, `sessionId`, `scenario`, `objective`, `learnerLevel`, `currentStep`, `lastAction`, and `locale`.

```bash
curl -X POST http://127.0.0.1:8787/v1/voice/turn \
  -H "Authorization: Bearer $IYNK_VOICE_CLIENT_TOKEN" \
  -H "Iynk-Client: iynkware-smoke/0.1.0" \
  -F audio=@speech.wav \
  -F sessionId=demo-session \
  -F scenario=chemistry_lab \
  -F objective='Teach the current procedure safely' \
  -F learnerLevel=beginner \
  -F currentStep=1 \
  -F lastAction='Selected the acid bottle' \
  -F locale=en-US
```

A successful turn returns the session ID, input transcript, response transcript, base64 PCM16 WAV and `audio/wav` media type. Errors use the canonical `{ "error": { "code", "message", "requestId" } }` shape and return the same request ID in the `X-Request-Id` header. Delete `/v1/voice/sessions/{sessionId}` with the same Bearer token to clear a conversation early.

## Deploy on Render

The root `render.yaml` defines a free Docker web service using `quest-voice-backend/Dockerfile`. Create a Blueprint from this repository after the repository owner approves cloud-resource creation. Supply `GEMINI_API_KEY` when Render asks; `IYNK_VOICE_CLIENT_TOKEN` is generated by Render. Automatic deploys are off because this repository has no hosted CI gate; deploy the reviewed commit explicitly.

After deployment:

1. Confirm `https://SERVICE.onrender.com/healthz` returns `ok: true`.
2. Copy the generated `IYNK_VOICE_CLIENT_TOKEN` from the Render environment.
3. Copy `integrations/unity/VoiceAssistant` into the Unity project's `Assets/Scripts` directory.
4. Add `VoiceAssistantClient` and `AudioSource` to a GameObject, set the HTTPS base URL and client token, then connect a world-space button with `PushToTalkButton`.
5. Add Android permissions for `android.permission.RECORD_AUDIO` and `android.permission.INTERNET` and request microphone permission at runtime.

Do not commit either secret. The demo token is extractable from an APK, so rotate it after the event. Production use should use the canonical server's device identity and per-user quotas.

## Quest build settings

- Android / Meta Quest target
- OpenXR
- IL2CPP and ARM64
- Internet Access: Require
- A visible disclosure that voice is AI-generated and the recording is sent to the configured provider

Conversation memory is process-local and expires. Keep one instance for the demo; use a durable store before horizontal scaling.

The demo service also caps each instance at 30 accepted voice turns per minute and two concurrent Gemini Live turns. Input is limited to 30 seconds of 16 kHz PCM and output to 4 MB. Client disconnects cancel the upstream Gemini session. These are cost and overload guards, not a substitute for per-user authentication in production.

`GEMINI_LIVE_MODEL` and `GEMINI_LIVE_VOICE` pin the upstream behavior; the Blueprint defaults to `gemini-3.8-live` and the `Puck` prebuilt voice. Change them in Render only after testing the replacement together, because unsupported voices fail during Live session setup.

The adapter emits localization keys such as `voice.listening` and `voice.unavailable`; the host Unity project supplies the visible strings. That keeps user-facing copy out of this repository's six-language WebXR message catalogue until the XR foundation defines its shared contracts.

The Unity adapter downmixes the hardware microphone channels and resamples the clip's actual frequency to mono 16 kHz before encoding WAV. This is required because Quest audio hardware may not honor the requested recording rate exactly.
